# Multi-Platform Local-First App: Architecture & Build Plan

**Agent Directive:** You are building a multi-platform (Web, Native Desktop, and CLI) local-first application. The core business logic is written in Go, the UI is built with React, and the database is SQLite. You must strictly adhere to the architecture and constraints defined in this document.

## 1. Core Constraints & Technologies

* **Monorepo:** The project must contain the Go backend, WebAssembly bridges, and React frontend in a single repository.
* **Web Target (Browser):** Compiled using **TinyGo** targeting `wasi` (WebAssembly Component Model), transpiled to an ES Module using `@bytecodealliance/jco`.
* *CRITICAL constraint:* Do NOT use `GOOS=js GOARCH=wasm` or `syscall/js`. Do NOT attempt to compile standard Go SQLite drivers into TinyGo, as TinyGo does not support CGO.


* **Desktop Target:** Bundled using the **Wails** framework. Uses standard Go and a pure-Go SQLite driver (`modernc.org/sqlite`) to avoid CGO cross-compilation issues.
* **Database Inversion of Control:**
* On Desktop: Go connects directly to the local filesystem SQLite database.
* On Web: Go imports a Host capability via `.wit`. The Web Worker runs `@sqlite.org/sqlite-wasm` connected to OPFS, and executes queries on Go's behalf.


* **Frontend UI:** React + TypeScript. Connects to Go via Wails IPC (Desktop) or a Web Worker + Comlink (Web).

## 3. Implementation Phases

### Phase 1: The Contract (`api/vfs.wit`)

Create the WIT file. This defines the API Go exposes to React, and the database capability Go imports from JavaScript.

```wit
package localfirst:vfs;

interface sqlite-host {
    execute-query: func(sql: string, params: list<string>) -> string;
}

interface types {
    record command-result {
        success: bool,
        output: string,
        error-message: option<string>,
    }
}

world app {
    import sqlite-host;
    use types.{command-result};
    export execute-cli: func(args: list<string>) -> command-result;
}

```

**Action:** Run `wit-bindgen go ./api/vfs.wit --out-dir internal/generated` to create the Go bindings.

### Phase 2: Go Database Abstraction (`internal/db`)

Define a shared `QueryExecutor` interface used by `internal/engine`.

1. **`db_native.go`** (`//go:build !wasm`): Implement the interface using `database/sql` and `modernc.org/sqlite`. Connect to a local file on disk.
2. **`db_wasm.go`** (`//go:build wasm`): Implement the interface by calling `sqlite_host.ExecuteQuery` (from `internal/generated`) and unmarshaling the JSON result.

### Phase 3: The TinyGo WebAssembly Build (`cmd/wasm`)

Create `cmd/wasm/main.go` that implements the exported functions from `api/vfs.wit` (e.g., `execute-cli`).

**Build commands:**

1. Compile: `tinygo build -target=wasi -o backend.wasm ./cmd/wasm`
2. Transpile: `npx jco transpile backend.wasm -o frontend/src/wasm --name backend --instantiation`

### Phase 4: Web Worker & SQLite Host (`frontend/src/worker.ts`)

Set up the Web Worker using `comlink`.

1. Initialize `@sqlite.org/sqlite-wasm` mapped to OPFS (`OpfsDb`).
2. Define the `localfirst:vfs/sqlite-host` capability, executing queries via the JS SQLite API and returning JSON.
3. Boot the JCO module (`frontend/src/wasm/backend.js`), injecting `@bytecodealliance/preview2-shim` AND the `sqlite-host` capability.
4. Expose the exported WASM functions to the main thread via Comlink.

### Phase 5: Desktop Implementation (`cmd/desktop`)

Initialize a standard Wails V2 project.

1. In the `App.startup` lifecycle hook, initialize `internal/db.NativeDB` with an OS-appropriate app data path.
2. Expose an `ExecuteCli` method directly to the Wails frontend.

### Phase 6: Universal React Adapter (`frontend/src/api.ts`)

Create a single API adapter that the React UI uses to communicate with the Go engine. It must auto-detect its environment:

* If `window.go` exists, route calls to the Wails backend.
* If `window.go` does not exist, spawn `worker.ts` and route calls via Comlink.

## 4. Automation (`Makefile`)

The agent must create a `Makefile` with at least these targets:

* `make generate`: Runs `wit-bindgen`.
* `make build-wasm`: Compiles TinyGo and runs `jco transpile`.
* `make dev-web`: Runs Vite for web development (depends on `build-wasm`).
* `make dev-desktop`: Runs `wails dev`.
